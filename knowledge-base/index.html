Как повторять

Сначала закрепите понятия, затем — операции и их сложность, после этого объясняйте решения вслух на примерах.

1. Основа

Язык

Типы, выражения, ветвления, циклы, массивы, функции, ссылки и исключения. Без этого ООП остаётся только терминологией.

2. Модель

Проектирование

Класс, объект, контракт, наследование, композиция и зависимости. Для каждого решения отвечайте: «кто за что отвечает?».

3. Эффективность

Алгоритмы

Определяйте доминирующую операцию, оценивайте время и память, выбирайте структуру данных под операцию.

4. Практика

Надёжность

Проверяйте граничные случаи, отделяйте зависимости и покрывайте поведение тестами.

Основы программирования — C++

Типы и значения

int, double, bool, char, string. Значимые типы хранят значение; ссылочные — ссылку на объект. null допустим для ссылочных и nullable-типов.

Управление потоком

if / switch выбирают ветку; for удобен при известном счётчике; while — пока истинно условие; foreach — перебор коллекции без индекса.

Функция как контракт

Сигнатура задаёт имя, параметры и возвращаемый тип. Аргументы передаются по значению; ссылка или указатель позволяют работать с исходным объектом. Функция должна иметь одну ясную ответственность.

int max(int a, int b) { return a > b ? a : b; }

Массивы, строки и указатели

Массив имеет фиксированную длину и доступ по индексу O(1). Указатель хранит адрес объекта; его нужно разыменовывать только для существующего объекта. Для строк и динамических массивов предпочтительны std::string и std::vector.

Исключения

Исключение сообщает об ошибочной ситуации, которую нельзя корректно продолжить в текущем месте. Перехватывайте только ожидаемые исключения; не используйте их для обычной логики.

Шаблоны

std::vector<T>, std::map<Key, Value> и собственные шаблоны позволяют писать один код для разных типов. constexpr переносит допустимые вычисления на этап компиляции.

ООП — C++

Класс и объект

Класс — описание состояния и поведения; объект — конкретный экземпляр. Инкапсуляция скрывает внутреннее представление и открывает безопасные операции через методы/свойства.

Наследование и полиморфизм

Наследование выражает отношение «является». Базовый тип задаёт общий контракт, наследник уточняет реализацию. Полиморфизм в C++ требует виртуальных методов и обычно работы через ссылку или указатель на базовый класс.

struct Figure { virtual double area() const = 0; virtual ~Figure() = default; };
struct Circle : Figure { double r; double area() const override { return 3.14*r*r; } };

Интерфейс и абстрактный класс

В C++ интерфейс обычно выражается абстрактным классом с чисто виртуальными методами. Базовый класс может содержать общую реализацию и состояние; избегайте наследования, если достаточно композиции.

Композиция

«Содержит» обычно лучше «является»: объект получает нужное поведение через поле/параметр. Так зависимости проще заменить в тесте и развивать независимо.

SOLID — практическая памятка

S — одна причина менять класс. O — расширять без переписывания устойчивого кода. L — подтип не ломает ожиданий базового типа. I — маленькие целевые интерфейсы. D — зависеть от абстракции, а не конкретного класса.

Внедрение зависимостей

Зависимость передаётся извне, чаще через конструктор. Это делает требования класса явными и убирает жёсткую привязку к конкретной реализации.

class ReportService {
  IClock& clock_;
public: explicit ReportService(IClock& clock) : clock_(clock) {}
};

АСОИУ — C#

Практический раздел курса: моделирование данных, структуры и коллекции, файлы, архитектура приложений и тестирование.

Точка входа и аргументы

Приложение начинается в Main или использует операторы верхнего уровня. Аргументы командной строки находятся в args; проверяйте их число до обращения по индексу. Завершайте программу кодом 0 при успехе и ненулевым кодом при ошибке.

string mode = args[0].ToLower();
if (mode == "where") return RunWhere(args);
return 0;

Типы, null и исключения

Значимые типы (int, double, bool) хранят значение; ссылочные хранят ссылку и могут быть null. Используйте ? для возможной пустой ссылки и бросайте конкретные исключения, например ArgumentException или ArgumentOutOfRangeException.

Классы, свойства и первичный конструктор

Класс объединяет данные и операции. Свойство отделяет внешний контракт от хранения данных. Первичный конструктор и выражения => сокращают простой код, но не должны прятать сложную логику.

internal class Circle(double radius) : Figure("Круг")
{
  public override double Area => Math.PI * radius * radius;
}

Полиморфизм: фигуры

Абстрактный Figure задаёт обязательное свойство Area; Circle, Rectangle и Square дают свою формулу. Код, принимающий Figure, не зависит от конкретного вида фигуры.

abstract class Figure(string type) {
  public string Type { get; } = type;
  public abstract double Area { get; }
}

Интерфейсы и сравнение

IEnumerable<T> добавляет возможность foreach; IComparable задаёт порядок для сортировки. Собственный интерфейс позволяет передать алгоритму нужное поведение — например, правило того, какое значение матрицы считать пустым.

Обобщения

List<T> хранит последовательность, Dictionary<TKey,TValue> ищет по ключу, а Matrix<T> или SimpleList<T> работают с любым подходящим типом. Ограничение where T : IComparable разрешает вызвать CompareTo внутри универсального класса.

Разреженная матрица

Не храните большую матрицу целиком, если большинство ячеек пустые. В примере курса значения лежат в Dictionary<(int x, int y), T>: память расходуется на заполненные клетки. Индексатор this[x, y] даёт доступ как к обычной матрице и обязан проверять границы.

readonly Dictionary<(int x, int y), T> data = [];
public T this[int x, int y] {
  get => data.TryGetValue((x, y), out var v) ? v : empty;
  set => data[(x, y)] = value;
}

Связный список и стек

Узел списка содержит данные и ссылку Next. Храните first, last и Count: добавление в хвост будет O(1). Стек строится поверх списка: Push добавляет, Pop возвращает и удаляет последний элемент.

CSV: чтение и запись

Работайте со входом через TextReader, а с выводом — через TextWriter: так функцию легко тестировать. Сначала считайте заголовки, затем строки. Проверяйте пустой вход, отсутствие колонки, число полей и формат чисел.

using var reader = File.OpenText("data.csv");
string? line = reader.ReadLine();
if (line is null) throw new InvalidOperationException();

Операции над табличными данными

В семинарском коде реализованы аналоги SQL-операций: projection выбирает столбцы, where фильтрует строки, join объединяет таблицы по ключам, group_avg группирует и считает среднее. Сначала найдите индекс столбца по заголовку, затем перебирайте строки.

SOLID и внедрение зависимостей

Разделяйте чтение CSV, обработку таблицы и вывод: это принцип одной ответственности. Зависимость передаётся в конструктор как интерфейс, а не создаётся внутри класса. Так алгоритм не связан с файловой системой, временем или конкретным хранилищем.

Тестирование

Тестируйте поведение, а не внутренние поля: обычный сценарий, границы и ошибки. Удобный шаблон — Arrange (подготовка), Act (действие), Assert (проверка). Для функций обработки CSV подайте StringReader и проверьте результат через StringWriter, не создавая реальные файлы.

Алгоритмы и оценка сложности

Асимптотика

O — верхняя граница роста, Ω — нижняя, Θ — точный порядок. Отбрасывайте константы и младшие члены: 3n² + 2n → Θ(n²).

Рекурсия

База останавливает вызовы, рекурсивный шаг уменьшает задачу. Для T(n)=aT(n/b)+f(n) сравните f(n) с n^log_b(a) (основная теорема).

Сортировки

Вставками: O(n²), лучший O(n), устойчива. QuickSort: среднее O(n log n), худшее O(n²), опорный элемент критичен. MergeSort: O(n log n), требует дополнительной памяти.

Поиск

Линейный поиск — O(n). Бинарный — O(log n), но только в отсортированной последовательности. Задача выбора k-го элемента решается QuickSelect в среднем за O(n).

Графы

Представление: матрица смежности удобна для проверки ребра; список смежности — для разреженных графов. DFS идёт в глубину и использует стек; BFS идёт по слоям и использует очередь.

Кратчайший путь

BFS даёт кратчайший путь в невзвешенном графе. Дейкстра работает при неотрицательных весах. A* выбирает минимум f(n)=g(n)+h(n); при допустимой эвристике находит оптимальный путь.

АСОИУ: качество, тесты и данные

Тестирование

Ошибка дешевле всего на этапе разработки. Тест описывает ожидаемое поведение: подготовка (Arrange), действие (Act), проверка (Assert). Проверяйте обычные, граничные и ошибочные сценарии.

Рефакторинг

Изменение внутренней структуры без изменения наблюдаемого поведения. Делайте маленькие шаги и запускайте тесты после каждого; сначала устраните дублирование и смешение ответственностей.

Файлы и CSV

CSV — строки записей с разделителями. Учитывайте кодировку, заголовок, пустые поля и кавычки. Валидация входа должна быть рядом с чтением данных.

Реляционные данные

Таблица состоит из строк и столбцов. Базовый SQL: CREATE/DROP меняют схему; SELECT читает; INSERT/UPDATE/DELETE меняют данные. WHERE фильтрует строки.

Самопроверка

Раскройте ответ только после собственной формулировки.

Чем интерфейс отличается от абстрактного класса?

Интерфейс описывает контракт возможностей и не хранит состояние экземпляра; класс может реализовать несколько интерфейсов. Абстрактный класс может содержать общую реализацию и состояние, но базовый класс только один.

Почему бинарный поиск нельзя запускать на произвольном массиве?

Его решение «отбросить половину» верно только если элементы упорядочены. Иначе положение среднего не говорит, где находится искомый элемент.

Когда BFS находит кратчайший путь?

В невзвешенном графе или когда все рёбра имеют одинаковую стоимость: вершины рассматриваются по неубывающему числу рёбер от старта.

Что нарушает принцип единственной ответственности?

Класс, который одновременно хранит данные, считает бизнес-правила, читает файл и выводит в консоль: у него несколько независимых причин измениться.

Как проверить корректность рекурсивной функции?

Назвать базовый случай, доказать уменьшение задачи и проверить, что рекурсивный шаг сохраняет требуемый результат. Для сложности составить рекуррентность.

Для чего передавать зависимость через конструктор?

Класс явно объявляет, что ему нужно, не создаёт конкретную реализацию сам и получает заменяемую зависимость — например, тестовый двойник.
